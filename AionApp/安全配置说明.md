# AionsHome 安全配置说明

## 📋 修复内容

本次修复解决了以下安全问题：

### 1. 敏感信息硬编码
**问题**：Supabase URL、ANON_KEY、服务器地址直接写在代码里，公开仓库可见

**修复**：改用 `BuildConfig` 从 `local.properties` 读取

### 2. 混淆规则缺失
**问题**：ProGuard 规则几乎为空，打 release 包会崩溃

**修复**：添加完整的混淆规则，保护 OkHttp、Compose、JSON 解析、数据类

---

## 🚀 快速开始

### 第一步：创建配置文件

复制 `local.properties.template` 为 `local.properties`：

```bash
cp local.properties.template local.properties
```

### 第二步：填写真实密钥

编辑 `local.properties`，把这一行：

```properties
supabase.anon.key=你的_anon_key_在这里
```

改成你真实的 anon key（以 `eyJ` 开头的长字符串）

### 第三步：同步并编译

1. 在 Android Studio 点击 **Sync Project with Gradle Files**
2. 编译：`./gradlew assembleDebug` 或点击 Run

## 🔒 安全注意事项

### ✅ 正确做法

- `local.properties` 只存在本地，**不提交到 Git**
- 已在 `.gitignore` 中排除 `local.properties`
- 团队成员各自创建自己的 `local.properties`
- 通过安全渠道（加密聊天、密码管理器）传递真实密钥

### ❌ 错误做法

- ❌ 把 `local.properties` 提交到 Git
- ❌ 在代码里硬编码密钥
- ❌ 在公开的 Issue、PR 里粘贴密钥
- ❌ 把密钥写在邮件、公开聊天记录里

## 📝 代码改动详情

### SupabaseClient.kt

**之前**：
```kotlin
const val URL = "https://byqqwypdfiwvalozihgs.supabase.co"
const val ANON_KEY = "eyJ..."
```

**现在**：
```kotlin
val URL: String = BuildConfig.SUPABASE_URL
val ANON_KEY: String = BuildConfig.SUPABASE_ANON_KEY
```

### build.gradle

添加了 BuildConfig 字段：

```gradle
defaultConfig {
    // ...
    Properties properties = new Properties()
    if (rootProject.file('local.properties').exists()) {
        properties.load(rootProject.file('local.properties').newDataInputStream())
    }
    
    buildConfigField "String", "SUPABASE_URL", "\"${properties.getProperty('supabase.url', 'https://byqqwypdfiwvalozihgs.supabase.co')}\""
    buildConfigField "String", "SUPABASE_ANON_KEY", "\"${properties.getProperty('supabase.anon.key', '')}\""
}

buildTypes {
    release {
        minifyEnabled true  // 启用混淆
        proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```

### proguard-rules.pro

添加了完整的混淆规则，保护：
- OkHttp / Okio
- JSON 解析类
- BouncyCastle
- Jetpack Compose
- WebView JavascriptInterface
- BuildConfig

## 🎯 为什么这样做

### 安全性
- 敏感信息不再出现在公开仓库
- 即使仓库泄露，攻击者也拿不到真实密钥

### 灵活性
- 开发/测试/生产可以配置不同的环境
- 团队成员可以用自己的测试账号

### 稳定性
- Release 包启用混淆不会崩溃
- 保护了关键类不被优化掉

## ❓ 常见问题

### Q: 为什么编译报错 "SUPABASE_ANON_KEY not defined"？
A: 没有创建 `local.properties` 或没有填写 `supabase.anon.key`

### Q: 我可以把 anon key 提交到 Git 吗？
A: 虽然 anon key 设计上可以公开（配合 RLS 保护），但最佳实践还是不要提交

### Q: 我的 local.properties 被 Git 追踪了怎么办？
A: 运行：
```bash
git rm --cached local.properties
git commit -m "chore: 移除 local.properties"
```

### Q: 团队新成员怎么配置？
A: 发给他 `local.properties.template` 和真实的 anon key，让他自己创建 `local.properties`
