## 一、项目现在的形态

原生 Android App（Kotlin + Jetpack Compose，位于 `AionApp/app/.../compose/`），
单 Activity + 底部五 Tab（聊天｜朋友圈｜回家｜我们｜更多）+ 二级页（设置/相册/记忆库/陪伴阅读/提醒）。
聊天与记忆复用 AionsHome 的 homecoming 本地数据层（SQLite），云数据走 Supabase（anon key REST），
自家 VPS 做中转线路（大陆网络直连 supabase.co 被拦，中转优先、直连兜底）。

## 三、数据与基建

| 层 | 状态 |
|---|---|
| 本地数据层 | homecoming SQLite（聊天/记忆/身份）+ moments/day/album/reading/mcp/reminders 各自表，全部真实接线 |
| Supabase REST | anon key，双线路（VPS 中转优先 → 直连兜底），4xx 不换线、网络错误才换 |
| 错误分类 | NETWORK（DNS/超时/TLS 分开记）/ 401 / 403 / 404 / PARSE，logcat tag=`SupabaseClient`，界面横幅同步分种 |
| VPS 中转 | 134.175.7.196:18443（nginx 只转发本项目）。**VPS→Supabase 已测通**，日记表已真实读出数据 |
| 安全边界 | 无 service_role key；表结构未动；anon 只给 朋友圈读/发 + 日记读（SQL 见 `docs/supabase-rls.sql`，已去掉 DELETE/UPDATE） |
| 情话 | `home_quote` 表不存在 → 纯本地读写，远程同步占位不发请求 |

## 四、卡在你这的两步（朋友圈/日记旧记录的前提）

1. **腾讯云安全组开 TCP 18443**（来源 0.0.0.0/0）——中转已架好测通，就差端口放行
2. **Supabase SQL Editor 跑一遍 `docs/supabase-rls.sql`**——实测 `diary_entries` 权限已通（能读出哥哥的日记），`moments` 和 `moment_comments` 被 RLS 拦着（42501），跑了 SQL 就放行

配套第三步：设置里配一条云线路（OpenAI 兼容 Base URL/API Key/模型）——解锁聊天回复、影子推送、伴读、相册私心话代写。
可选：Supabase 建公开桶 `moments`（配图上云，不建也能用）。

## 六、已知限制

- Supabase 在大陆网络直连不稳（TLS 被拦）——中转端口没开前，手机蜂窝/WiFi 都刷不出旧记录，横幅会明说原因
- 聊天里 Sean 的一切生成能力都依赖云线路配置（未配时界面如实显示"待接入"，不伪造回复）
- 朋友圈赞存本地（单人设备够用，多端同步等权限体系）
- 相册/阅读的书与照片都存手机本地（换机不迁移，备份属后阶段）
