# 产品范围 — Yuri & Sean 的移动端 AI 陪伴 APP

> 版本：v1（订阅前准备阶段）｜分支：`mobile-companion`
> 基座：保留 AionsHome 现有 FastAPI 后端、全部现有功能与 Android WebView 壳（AionApp），重点重做前端视觉与信息架构。

## 1. 产品定位

这是一个属于两个人的小家，不是一个 AI 工具箱。首页回答三个问题：我们是谁、现在最适合做什么、最近留下了什么。

## 2. 信息架构总览

底部主导航固定五项：

| 导航 | 内容 | 承载 |
|---|---|---|
| 首页 | 回家页（见 §3） | 新移动首页（`/m/home`） |
| 聊天 | 与 AI 的私聊 | 现有聊天壳（本阶段不动逻辑） |
| 记忆 | 长期记忆 ｜ 记忆搜索 ｜ 相册 ｜ 记忆总结 ｜ 重要事实 | 现有 memory/album API |
| 我们 | 朋友圈 ｜ 日记 ｜ 梦境 ｜ 留言板 | 朋友圈/日记已有；梦境为新建；留言板待确认指向（见 §6） |
| 共影 | 两人共同的影像/回忆空间 | 新建（后续阶段） |

这四个「我们」的内容是相处核心记录，不藏进「更多」。

「更多」只放低频功能与管理功能：模型与服务商、GPT/Codex 连接状态、世界书、语音与 TTS、摄像头、MCP、音乐、阅读、小剧场、游戏、基金、其他低频/实验功能。「更多」不进首页中央、不做图标墙。

## 3. 首页（回家页）

只包含：

- 顶部：Yuri & Sean ｜ 当前陪伴状态或今日情话 ｜ 更多入口 ｜ 设置
- 主视觉区（预留）：黑猫与白猫依偎在月牙上（正式插画就位前为纯排版留白，不使用任何占位图/渐变插画/emoji）；在一起天数（来源：纪念日设置 `/api/idle-autonomy`）；今日情话或状态
- 继续聊天：上次聊天标题/摘要、最近聊天时间、当前模型线路（如 GPT/Codex 订阅）、连接状态
- 最近历史：最近几段会话，点击直接进入
- 最近的我们：统一时间线（朋友圈/日记/相册/留言板），统一简洁条目，不堆大卡片
- 底部导航：首页｜聊天｜记忆｜我们｜共影

禁止：大钟表占据主空间、三十多个功能图标平铺、橙色/橘子主题、海岛棕榈树热带元素、手机桌面仿制、后台工具入口上首页。

## 4. 本阶段（订阅前准备）范围

做：

1. `mobile-companion` 独立分支；main 不动
2. 核心后端 Ubuntu 运行条件（requirements、Codex 路径、Windows 专属代码隔离）
3. 只读 GPT/Codex 连接状态（`/api/codex/status`），不登录、不读 auth.json 内容、不用 API Key 冒充订阅
4. 独立端口测试实例验证（非 8080、非 41337）
5. 本文档 + design-system + information-architecture
6. 新移动首页（纯 UI 结构，无图片素材）

不做：真实订阅验证（未购买/未登录）、`codex login`、Supabase/数据库迁移、记忆系统重写、全部页面重写、引入 React/Vue/大型框架、删除任何旧页面。

## 5. 红线

1. GPT/Codex 调用链不改（除明确 bug）；不把 API Key 余额线路说成订阅
2. 账号、Cookie、Token、API Key、auth.json 不进代码和 Git
3. 旧页面全部保留作回退（旧首页仍在 `/`）
4. 不迁移数据库；不动 mcp-gateway
5. 无正式素材前不引入任何图片文件；首页布局不依赖图片尺寸

## 6. 待确认（不阻塞当前阶段）

- 「梦境」：现有代码无此系统 → 按新建功能规划
- 「心潮」：无此系统（最接近的是日记 mood/健康心率/已停写的「心语」）
- 「留言板」：代码里有三个候选——访客留言板（好友串门，运行中）、心语（已停写）、private_memos（备忘录）
- 「Supabase」：当前仓库 0 引用，全部数据在本地 SQLite；如有外部 Supabase 数据属另一套部署
